# ADR-0003 操縦：SoftAP＋WebSocket＋ブラウザUI

- 状態：決定（2026-11-01）

## 背景
Androidスマホで操縦したい。開発期間はできるだけ短くしたい。

## 選択肢
| 案 | 長所 | 短所 |
|---|---|---|
| A. ESP32がWi-Fiアクセスポイントになり、HTMLのジョイスティック画面を配信。WebSocketで通信 | アプリ開発が不要。ブラウザがあればどの端末でも動く。UIをHTML/JSで手早く変更できる | ブラウザの描画分の遅延がある（数十ms程度） |
| B. Androidネイティブアプリ＋BLE | 遅延が小さく、UIを自由に作れる | Kotlinでのアプリ開発が別途必要になり、期間が延びる |
| C. 市販のRC送信機＋受信機 | 操作感が最も良い | 追加費用がかかる。スマホ操作という要求に合わない |

## 決定
A を採用する。

## 理由
- アプリ開発が不要になり、期間短縮の効果が大きい
- 遅延の要求（REQ-P06：100ms以下）は満たせる見込み。Phase 1で実測して確認する
- テレメトリ（姿勢角・電圧）も同じ画面に表示できる
